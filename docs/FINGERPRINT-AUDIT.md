## Portability and privacy findings

- No real `.env`, `.env.local`, credential/private-key file, or symlink was observed by the inventory; only `.env.example` templates. The narrow token/private-key pattern scan found no confirmed secret: its two hits were task-identifier false positives at `backend/tests/unit/test_youtube_proxy_download.py:66` and `docs/editor.md:65`. This is not proof that every arbitrary high-entropy value or binary is safe.
- No hardcoded Telegram numeric routing identifier was detected in snapshot text. A Telegram delivery reference remains at `docs/remotion-rendering.md:11`; uploader and profile routing are a separate parent deliverable, not implemented by the renderer.
- Remaining personal absolute-path references observed: `docs/local-native-runtime.md:8`, `docs/premium-podcast-quickstart.md:19`, `remotion/test/artifacts/graphics-smoke/job.json:2–4,54`, and `remotion/test/artifacts/graphics-smoke/verification.json:2`. Replace path-specific instructions; remove or parameterize stale artifact JSON. Do not retain `.task-monitor-id` as portable package state (it was present in the initial inventory).
- The newly observed `remotion/browser.mjs` supports installed Chrome/Chromium discovery on macOS/Linux/Windows and `REMOTION_BROWSER_EXECUTABLE`; `node --check` passed. This supersedes the original Mac-only renderer default seen earlier in the audit. It does not establish real cross-platform render success. Update `docs/remotion-rendering.md:24` to match discovery behavior.
- `scripts/creator_local_atlas_fallback.py:30` still assumes Apple's proprietary system emoji font. It is not portable and is not a license to redistribute that font. Its Pillow rasterization is a distinct fallback, not proof of pixel equivalence with Chrome; explicitly disclose and review outputs.
- Many older `render_*`, `prepare_*`, `verify_*`, `check_*` and DDG/Serhant/Dana helpers have fixed relative cache paths, fixed episode timings, and top-level execution. They are historical recipes, not safe importable libraries or generic commands. Some represent rejected/superseded treatments (`render_holiday_strikes.py`, early flash/riser paths); separate them from the supported entrypoints to avoid accidentally recreating rejected styling.

## Security boundaries and operational hazards

- **Trusted local editor tools only.** Remotion stages explicit media/font/optional assets into isolated temporary directories and guards output/input alias collisions (`remotion/schema.mjs:67–68`). Creator renderer refuses existing output and validates local TrueType assets (`remotion/creator-schema.mjs:89–101`). These are useful safeguards, not an authentication or tenant sandbox. Do not expose arbitrary local paths/jobs as a public render API.
- `remotion/render.mjs` deliberately overwrites a non-input destination; FFmpeg helpers commonly use `-y`. Prefer fresh output directories and explicit overwrite consent. The creator Python engine has weaker preflight than its JS graphics validator and accepts trusted plans rather than comprehensive untrusted-input validation.
- Dynamic `exec(compile(...))` is present in `scripts/refine_serhant_audio_fx.py:85–87`, `scripts/finish_serhant_1_2.py:28–30`, and `scripts/render_john_campaign.py:15–18`. It extracts functions from local scripts, not remote/user text, but couples behavior to trusted source. Refactor to a normal helper module before broader automation.
- Do not run every script as a smoke test: `scripts/setup-media-storage.py:28–33` contacts cloud identity even without `--apply`; with apply it creates/changes cloud resources and credentials. `scripts/local_verify.py:49` enqueues cleanup, and `:77–78` contacts a hosted provider. `scripts/monitor-production.py:54,60,66` contacts a production site/SSH host. `scripts/prepare_ddg_batch.py:23` and `scripts/validate_reframing.py:162` can download media. Label these as operational/network tools and exclude them from offline verification defaults.
- Optional observability mounts Docker socket and host logs (`docker-compose.yml:443–446`); keep that profile disabled unless explicitly intended and understand host-level access. Loopback service bindings are a positive default, not a complete production security review.

## Asset, model and reproducibility constraints

- Root `LICENSE` preserves SupoClip AGPL terms; distribute modifications with required corresponding source/notices and consider network-use obligations. Remotion is separately licensed: existing docs describe historical v4 eligibility; recheck terms/organization eligibility before commercial use. No live license lookup was performed because network activity was excluded.
- Bundled YuNet model SHA-256 matched `backend/src/media/models/README.md:11`; its MIT notice is included. That detector proves face localization only, not editorial or gameplay understanding.
- Whisper checkpoints are not included. `podcast_pipeline.py:528–551` requires an existing trusted `.pt` path and uses CPU, avoiding implicit model downloads. Backend `_get_whisper_model` (`backend/src/media/transcription.py:177–185`) loads by name and may download/cache a model. The default backend transcription provider is hosted AssemblyAI (`backend/src/config.py:25–27`); switching to Whisper does not automatically make LLM analysis offline. Set and separately verify the LLM provider. Hermes model access is not SupoClip inference access.
- Keep frontend and Remotion pnpm lockfiles and backend `uv.lock`; keep Remotion packages on the same exact version. No dependency trees/venv are bundled. Reusable scripts need NumPy/Pillow/OpenCV; older helpers additionally import imageio-ffmpeg/SciPy. Several are not explicit top-level backend dependencies, so transitive availability is not a portable installation contract. Provide a tested extras/dependency manifest for supported scripts, not every historical recipe.
- Need local FFmpeg/ffprobe, required filters/codecs (including libass for legacy ASS paths), installed browser, Node/pnpm and Python dependencies. Document CPU/CUDA/platform choices; no GPU is required by the manual podcast transcription path. Offline execution additionally requires pre-provisioned models, browser, packages and source assets.
- Reproducibility is recipe/timeline-level, not bit-identical output across browser/FFmpeg/font versions. Pipeline resume hashes outputs/code but identifies large source inputs by path/size/mtime (`docs/podcast-pipeline.md:99`); preserved-size/mtime replacements can evade invalidation. Pin tool versions and record asset checksums for archival replay.
- Existing docs reference absent output manifests, review sheets, approved MP4s and source audits. Preserve these as historical claims, not packaged proof. A synthetic fixture plus fresh clean-machine technical report is the practical release gate; then manually review a rights-cleared podcast clip and a rights-cleared creator clip. Gaming remains a separate validation programme.

## Suggested minimum release gate

1. Fix invalid transition, license/asset notices, native bootstrap and creator fps/path mismatch.
2. Remove stale personal paths/state/artifact claims; list supported commands versus episode recipes and network tools.
3. Create fresh secrets locally, keep credential files private, and leave hosted/cloud integrations off until configured intentionally.
4. On a clean machine, install from locks and run supported unit tests plus generated-source podcast/creator renders with no network/model downloads during rendering. Record exact tool versions and output checksums.
5. Probe/full-decode real outputs; run all-frame regression checks with reviewed effect exclusions, inspect every transition/framing extreme, and listen to opening/closing words. Keep visual/editorial approval pending until actually performed.
