# SupoClip operations

## Locations
- Checkout: `${CLIP_ROOT}`
- Hermes home: `${HERMES_HOME}`
- Upstream docs: checkout `docs/`, especially setup, configuration, architecture and API reference. `mcp/README.md` documents the MCP contract.
- MCP launcher: profile `scripts/supoclip-mcp.py`. It reads secrets locally from repo `.env` / `.env.local` and profile `.env` and never stores credentials in config.yaml. Default endpoint is `http://127.0.0.1:8000`, not the paid hosted API.
- Download directory: `${CLIP_ROOT}/outputs`.

## Preflight
1. Call `mcp_supoclip_supoclip_health`. Tool discovery alone does not prove a backend is available.
2. Check authenticated `supoclip_list_tasks` before submitting a job. If auth fails, inspect local setup without printing secret values.
3. Check transcription and LLM configuration separately. Hermes uses the operator-selected model/provider; SupoClip does NOT automatically inherit that model access. Local Whisper is an upstream-supported alternative to AssemblyAI. No purchases or new paid service activation without the operator's approval.
4. Inspect the source video metadata. Confirm source availability and output requirements; default vertical 9:16 captioned shorts. Ask only when a missing decision prevents work.

## Workflow
- With every video delivery, including revised clips, provide its matching Instagram post caption and relevant hashtags in a fenced plain-text code block for easy copying. Label each block clearly with the corresponding clip; deliver it alongside the video rather than waiting for the operator to ask. This post copy is separate from burned-in dialogue captions and the uploader's short file label.
- Use MCP caption-template and font listing tools to inspect available styles.
- Submit a task with `supoclip_create_clip_task` or `supoclip_create_clip`, preserving the actual returned task ID.
- Poll `supoclip_get_task` or `supoclip_wait_for_task` until a terminal status. Keep identifiers exact. Report failures honestly; never count queued or failed clips as rendered.
- Keep MCP wait calls below the transport's 300-second timeout (use 240 seconds), then repeat as needed. A transport timeout does not mean the worker stopped; read the task before retrying.
- Model visibility checks do not prove inference works. If analysis fails with HTTP 429, inspect task-specific worker warnings and distinguish an observed rate/quota rejection from an unverified billing diagnosis. Do not purchase credits or switch to a paid fallback automatically.
- Download with `supoclip_download_clip`, or export with `supoclip_export_clip` for TikTok, Reels or Shorts. Do not publish to those services without an explicit request.
- Use ffprobe on actual downloaded files. Check playability, duration, aspect ratio and audio; inspect rendered captions and start/end cuts before calling them final.
- For Telegram clip delivery, use the portable verified uploader (requires the operator's own HERMES_HOME and explicit --chat) rather than relying on raw `MEDIA:` tags: `backend/.venv/bin/python ${CLIP_ROOT}/scripts/deliver_clip.py /absolute/clip.mp4 --caption 'Clip label'`. It reads only clipping's secret `.env`, uses fresh IPv4 HTTP/1.1 curl uploads with extended timeouts, bounded retries, document fallback, serial locking and SHA-256 dedupe receipts under profile `delivery/`. It confirms the target chat/message media result and separately reads the remote file back with `getFile`. Require `status=confirmed` and a real `message_id` before saying Telegram accepted the file. Do not append another MEDIA tag after a successful direct send, which duplicates delivery. `--force` is only for an intentional resend. Failed jobs remain as pending records for explicit retry, not a claimed success.
- Keep the Telegram playback copy below 19 MiB when delivery requires Bot API `getFile` readback. A larger video may be accepted by `sendVideo` yet `getFile` can reject it as `Bad Request: file is too big`; inspect the persisted accepted receipt before retrying so an acknowledged upload is not duplicated. Retain the high-quality master and make a separate bitrate-capped H.264 copy, copying the approved AAC audio where possible. Verify that copy's dimensions, frame count, duration, decode and actual frames, then upload and confirm its own remote readback.
- Raw Hermes MEDIA delivery previously failed with `httpx.ReadError` and fell back to a warning text rather than an actual attachment. This uploader bypasses that transport for clipping; it does not patch the shared gateway or guarantee that the user has watched/downloaded a message. Never equate a local render or successful text warning with video delivery.
- Deliver actual MP4s using `MEDIA:/absolute/path/file.mp4` only when no verified uploader is available, and treat receipt as unconfirmed until checked.

## Audience-first styling
- Establish an audience/style brief before selection or rendering: niche, intended viewers and their familiarity with the subject, platform, campaign rules and supplied references. State reasonable assumptions when demographics are unknown; do not invent audience analytics or ask needless questions when the source makes the niche clear.
- Adapt hooks, typography, caption density, cut cadence, zooms, emoji and effects to that audience rather than transplanting one niche's winning template into another. Audience fit and explicit campaign direction override the earlier podcast house-style defaults.
- Treat the operator's course examples as starting hypotheses, not universal demographic facts or mandatory fonts: youth-oriented gaming/Roblox may suit playful Comic Sans-like typography, short captions and energetic changes around every 2–3 seconds; broad/older professional audiences may suit clean Montserrat-like white captions, clear non-exaggerated hooks and steadier pacing. Confirm against actual niche references and available performance data, and preserve accessibility/readability in either case.
- For finance, business and technical interviews, prioritize credibility, context and comprehensible explanations over constant stimulation. Do not force emojis, aggressive hooks, flashes or three-second scene changes. Preserve the hook→pacing→payoff structure while changing its execution for the audience.

## Editorial selection: hook → pacing → payoff
- Apply the operator's expanded short-form framework in `references/short-form-editorial-principles.md` when selecting, writing heroes, pacing and reviewing clips. Identify the first-three-second hook, specific curiosity question, real emotional/share trigger and resolved payoff; test a natural replay seam when warranted. Treat course algorithm/earnings claims as unverified hypotheses, not guarantees or a reason to override campaign length requirements.
- For future interview/podcast clips, the operator approves this source-supported structure when the host asks a strong COMPLETE question: impactful guest statement as a cold-open hook → approved semantic flash/transition into the ORIGINAL host question → guest's substantive body answer → payoff/clean ending. Include the actual question before the body, not before the cold-open hook. Prefer a hook excerpt that teases rather than exhausts the payoff, and avoid needless verbatim repetition when the answer resumes. Preserve who said what, enough context and the meaning of the exchange; never fabricate a question, splice unrelated prompts into a false exchange, or imply the reordered hook originally preceded the question. Show the host while the complete question is asked, not a momentary reaction flash. Interpret 'flash to the question' as an editorial transition, not strobing; reuse approved restrained treatment where appropriate and allowed. If the host only offers a setup statement, trails off, is interrupted, or the question is weak/redundant, omit it rather than forcing this structure. the operator specifically chose to leave Steven's entrepreneurship setup OUT of the current Dana edit; do not revise it to insert that reference excerpt. This rule is editorial guidance, not a claim of automatic question detection or a newly rendered clip.
- Apply the operator's supplied ideation framework to selection and editing: the hook captures attention, pacing maintains it, and payoff rewards it. Shortlist candidates by identifying all three before rendering; do not assume strong subject matter alone makes a strong short.
- Open with a source-supported statement that raises a specific question, stakes or curiosity. Where appropriate, preview the real payoff and cut before the reveal/reaction, then deliver it in context. Never fabricate stakes, misrepresent chronology or add outside hooks when campaign rules prohibit them.
- Evaluate the opening picture alongside the spoken hook: the viewer must see the setting/action that makes the words compelling. Preserve relevant gameplay, stakes and facial reactions instead of blindly face-cropping everything.
- Convert long-form pacing deliberately: flag empty pauses longer than 0.5 seconds for removal, along with repetition and irrelevant detours. Preserve meaningful suspense, natural breaths, consonant onsets and intelligibility; the threshold is a review heuristic, not automatic silence deletion.
- Review visual engagement about every three seconds. Use motivated source shot changes, modest punch-ins or meaningful emphasis where a static shot loses interest; adapt cadence to niche/reference footage. Do not force arbitrary cuts, flashes, unrelated inserts or repetitive reactions. The existing minimum three-second listener-shot hold still applies.
- Identify the promised payoff explicitly. Where natural, place it around the third quarter/late in the clip and close promptly after it lands; do not pad a clip to hit a percentage or truncate an important conclusion. Treat the supplied sentence saying the hook answers questions as a terminology slip: resolution belongs to the payoff.
- Before delivery, check: what question does the opening create, what keeps the middle moving, where is that question resolved, and does anything unnecessary follow? Use available real retention/average-view-duration data to improve choices; never guarantee virality or assert a deterministic algorithm boost.

## Creator caption direction
- the operator wants fast, smooth pacing by cutting thinking pauses where the speaker stops for a second or two. Shorten dead air, not the spoken delivery: retain consonant onsets, short natural breaths, meaningful reactions and punchline timing. Inspect detected quiet regions before cutting because low-level speech is not dead space. Trim picture, audio, captions and persistent hero together on a shared frame timeline; do not speed up the voice. The tightened DDG recognition edit demonstrates six reviewed pause cuts with 100ms tail/120ms onset handles; these handles and silence thresholds are review aids, not universal automatic rules.
- the operator's standing hero-headline direction is funny, meme-style, brain-rot, scroll-stopping satire for short-form videos. Apply this to hero wording, not the verbatim spoken captions: use source-specific absurdity, ironic framing and internet-native humour rather than descriptive summaries or generic labels such as “Instant regret.” Keep the joke grounded in the actual scene; never fabricate quotes, allegations or stakes. Preserve readability, persistent placement and face/action safety. Explicit campaign or clip-specific instructions override this default; do not change the locked podcast visual treatment merely to implement different hero wording.
- For sync revisions, compare actual rendered picture frames against source timestamps and audio waveforms against the source; matching stream start/duration fields alone does not prove lip sync. Prefer native source frame rate and a common frame-boundary A/V trim. Never guess a large audio delay from captions or claim source-intrinsic lip sync is certified by waveform correlation. Review the extreme of every zoom/physical lean: nominal crops that pass at sparse samples can cut the head at peak motion. Reuse verified transparent captions for picture-only changes; extend a static hero as a separate alpha layer rather than rerendering an unchanged long caption sequence.
- On the operator's cropped creator videos, keep the separate hero headline visible throughout the clip, not only in the opening. Position it in the available top safe area without obscuring faces or action; set its end explicitly to the full edited duration. For monetization-led work, select a complete substantive story/sequence and establish the target programme's actual eligibility requirements; do not pad weak material or guarantee monetization from duration alone. - For the operator's separate creator/high-energy format, show ONLY ONE spoken-caption word at a time, centered, with an individual pop-in on its spoken onset. ## Native runtime recovery
The API and worker run as detached native processes. After reboot, start Docker and run from `${CLIP_ROOT}`:
```sh
docker-compose --env-file .env.local -f compose.local-infra.yml up -d --wait
backend/.venv/bin/python scripts/local_runtime.py start
backend/.venv/bin/python scripts/local_runtime.py status
```
See repo `docs/local-native-runtime.md` for exact service handles and tests. The Hermes Telegram gateway has launchd auto-start, but this does not auto-start SupoClip's native backend/worker. Do not confuse the two.
